# File size allowlist — the ratchet.
#
# Every file listed here is over its limit (300 lines for a backend .cs, 200 for
# a frontend .component.ts) and is allowed to stay that way at EXACTLY the
# recorded size.
#
#   - It grows  -> the build fails. This is the point.
#   - It shrinks -> the build also fails, asking you to record the new number.
#     That is what makes the list ratchet downward instead of drifting, and what
#     puts every improvement in the diff where a reviewer sees it.
#   - A file NOT listed here may not cross its limit at all.
#
# Nothing here is a defect. Size is a tripwire, not a verdict — see
# DOCS/ASSERTIONS_AND_ASSUMPTIONS.md §1.4, which found that size ranks almost
# opposite to movability. Crossing the line means someone should look, not that
# the file is wrong.
#
# Regenerate the counts (from the repo root):
#
#   { find annas-archive-api/src -name '*.cs' -not -path '*/obj/*' -not -path '*/bin/*'; \
#     find annas-archive-app/src/app -name '*.component.ts' -not -name '*.spec.ts'; } \
#   | while read -r f; do n=$(wc -l < "$f" | tr -d ' '); \
#       case "$f" in *.cs) lim=300;; *) lim=200;; esac; \
#       [ "$n" -gt "$lim" ] && printf '%s\t%s\n' "$n" "$f"; done | LC_ALL=C sort -t$'\t' -k2,2
#
